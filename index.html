How I work

Three habits that survive a deadline

01

Verification over generation

An agent can produce working code faster than I can be confident it is correct. So the work moves to designing the check: the test, the reconciliation, the thing that notices when the output is quietly wrong.

02

The abstraction is the deliverable

A change that satisfies the ticket but breaks the shared layer is not done. I write that standard down and hold it, because the next engineer inherits the abstraction, not the ticket.

03

If it fails, it should say so

A job that reports its own failure is worth more than one that runs faster. Observability is part of the feature, not a later ticket.
